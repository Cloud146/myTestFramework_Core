# Пакет TestUtils.RetryUtil

Пакет **`TestUtils.RetryUtil`** реализует механизм автоматического перезапуска (Retry) неудачных тестов.
Это стандартная практика в UI-автоматизации для борьбы с "мигающими" (Flaky) тестами, которые могут падать из-за
временных проблем инфраструктуры, сети или рендеринга браузера.

Пакет интегрируется с TestNG через интерфейсы `IRetryAnalyzer` и `IAnnotationTransformer`.

---

## 1. Класс `RetryAnalyzer`

Реализация интерфейса `IRetryAnalyzer` из TestNG.
Определяет логику принятия решения: нужно ли перезапускать тест, который только что упал, или признать его окончательно
проваленным.

### Поля класса

| Поле             | Описание                                                                                                        |
|:-----------------|:----------------------------------------------------------------------------------------------------------------|
| **`attempt`**    | `int` (stateful). Счетчик текущей попытки перезапуска для конкретного экземпляра теста. Изначально `0`.         |
| **`maxRetries`** | `int` (final). Максимально допустимое количество перезапусков. Значение считывается из глобальной конфигурации. |

### Конструктор

| Конструктор           | Логика инициализации                                                                                                                                                                                                                             |
|:----------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`RetryAnalyzer()`** | 1. Обращается к `RuntimeReader.getSection("retry")` для получения секции настроек.<br>2. Извлекает значение `count`.<br>3. Инициализирует поле `maxRetries`. Если настройка отсутствует, используется дефолтное значение `0` (ретраи отключены). |

### Метод `retry`

Вызывается TestNG каждый раз, когда тестовый метод завершается с ошибкой (Exception или Assertion Error).

| Метод       | Параметры            | Алгоритм работы                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|:------------|:---------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`retry`** | `ITestResult result` | 1. Сравнивает текущий счетчик `attempt` с лимитом `maxRetries`.<br>2. **Если лимит не исчерпан (`attempt < maxRetries`):**<br>    * Инкрементирует счетчик `attempt++`.<br>    * Формирует информационное сообщение ("Перезапуск #1 из 2...").<br>    * Логирует сообщение в консоль (`log.info`).<br>    * Добавляет шаг в отчет Allure (`Allure.step`), чтобы в отчете было видно факт перезапуска.<br>    * Возвращает `true` (сигнал TestNG перезапустить тест).<br>3. **Если лимит исчерпан:**<br>    * Возвращает `false` (тест помечается как Failed). |

## 2. Класс `RetryListener`

Реализация интерфейса `IAnnotationTransformer` из TestNG.
Позволяет динамически модифицировать аннотации `@Test` для всех методов во время компиляции/загрузки классов, избавляя
от необходимости прописывать `retryAnalyzer = RetryAnalyzer.class` вручную над каждым тестом.

### Метод `transform`

| Метод           | Параметры                                            | Описание и Логика                                                                                                                                                                                                                                                        |
|:----------------|:-----------------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`transform`** | `ITestAnnotation annotation`, `Class testClass`, ... | Метод перехватывает метаданные каждого тестового метода.<br>**Логика:**<br>Вызывает `annotation.setRetryAnalyzer(RetryAnalyzer.class)`.<br>Это программно "навешивает" наш анализатор ретраев на абсолютно все тесты в проекте, которые запускаются через этот Listener. |
