# Пакет TestUtils.Helpers

Пакет **`Helpers`** содержит вспомогательные утилиты, слушатели (Listeners) и менеджеры, которые обслуживают
инфраструктуру тестов.
Здесь сосредоточена логика инициализации (Bootstrap), управления адаптерами и связывания тестов с данными.

---

## 1. Класс `AdapterManager`

Ключевой компонент для реализации модульности. Отвечает за динамическое создание экземпляров `DriverAdapter` на основе
настроек.
Использует механизм **Java SPI (Service Provider Interface)** для обнаружения доступных реализаций (Selenium,
Playwright) в classpath, не имея жесткой зависимости от них на этапе компиляции.

### Методы

| Метод               | Параметры               | Описание и Алгоритм                                                                                                                                                                                                                                                                                                                                                                                                                    |
|:--------------------|:------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`createAdapter`** | `String engine`         | Фабричный метод.<br>**Алгоритм:**<br>1. `ServiceLoader.load(DriverAdapterFactory.class)` — сканирует все JAR-файлы и ищет реализации фабрик.<br>2. Перебирает найденные фабрики (Stream API).<br>3. Фильтрует их: сравнивает `factory.getEngineName()` с переданным параметром `engine` (например, "selenium").<br>4. Если подходящая фабрика найдена — вызывает `factory.create()`.<br>5. Если нет — бросает `IllegalStateException`. |
| **`closeAdapter`**  | `DriverAdapter adapter` | Безопасно закрывает драйвер. Проверяет на `null` перед вызовом `adapter.close()`.                                                                                                                                                                                                                                                                                                                                                      |

## 2. Класс `LoggingBootstrapListener`

Слушатель TestNG (`ITestNGListener`), который гарантирует **самую раннюю инициализацию** системы логирования.
Благодаря тому, что этот листенер прописан в `META-INF/services/org.testng.ITestNGListener`, он загружается TestNG одним
из первых, еще до старта каких-либо тестов.

### Блок статической инициализации

Процесс происходит в блоке `static { ... }`:

1. **`LogbackConfigurator.initFromRuntime()`**: Читает путь к конфигу логгера из `runtime.yaml` и применяет его.
2. **`JulBridge.init()`**: Устанавливает мост `java.util.logging -> SLF4J`.
3. Логирует сообщение об успешной инициализации.

Это гарантирует, что даже логи самого TestNG или Selenium будут перехвачены и отформатированы нашим логгером.

## 3. Класс `FrameworkDataInitializer`

Утилитный класс-фасад для централизованной загрузки тестовых данных и настроек перед стартом сьюта.
Обычно вызывается в `@BeforeClass` методе `BaseTest`.

### Методы

| Метод                | Возвращает | Описание                                                                                        |
|:---------------------|:-----------|:------------------------------------------------------------------------------------------------|
| **`initTestData`**   | `void`     | Делегирует вызов `TestDataService.initIfNeeded()`. Запускает сканирование папки с YAML-данными. |
| **`initRetryCount`** | `int`      | Читает секцию `retry` из `runtime.yaml` и возвращает количество попыток перезапуска (`count`).  |
| **`initTimeouts`**   | `Map`      | Читает секцию `timeouts` из `runtime.yaml` (если используется).                                 |

## 4. Класс `ScenarioLogger`

Отвечает за логирование имени текущего теста и установку контекста для Data Provider'а.
Используется в `@BeforeMethod` в `BaseTest`.

### Методы

| Метод                                    | Логика работы                                                                                                                                                                                                                      |
|:-----------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`logScenario`**<br>(`Method m`)        | 1. Вызывает `extractDescription(m)` для получения красивого имени.<br>2. Пишет в лог: `[TESTNG] Сценарий: ...`.<br>3. Вызывает `TestDataService.setCurrentScenario(...)`, связывая текущий поток с именем теста для поиска данных. |
| **`extractDescription`**<br>(`Method m`) | **Определяет имя сценария.**<br>1. Ищет аннотацию `@Test` над методом.<br>2. Если есть атрибут `description` и он не пустой — возвращает его.<br>3. Иначе возвращает техническое имя: `ClassName.MethodName`.                      |

## 5. Класс `AutoTagListener`

Слушатель TestNG (`ITestListener`), который автоматически добавляет метаданные (теги) в отчет Allure в зависимости от
типа теста.

### Методы (События)

| Метод                                       | Логика                                                                                                                                                                                                                                                                                                                                             |
|:--------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`onTestStart`**<br>(`ITestResult result`) | 1. Получает инстанс тестового класса.<br>2. Проверяет, является ли он наследником `AbstractTestNGCucumberTests`.<br>3. **Если это Cucumber:** Ничего не делает (теги проставляются Cucumber-ом из feature-файлов).<br>4. **Если это Java (TestNG):** Добавляет в Allure метку `tag: JavaIDE_Test`. Это позволяет легко фильтровать тесты в отчете. |
