# Глобальная конфигурация (Runtime)

Файл `runtime.yaml` — это единая точка входа (Entry Point) для оркестрации тестового прогона.
В нем определяются параметры окружения, стратегии запуска и конфигурация подключенных модулей.

Расположение: `Workspace/src/test/resources/configuration_files/runtime.yaml`

## 1. Базовые настройки окружения

Эти параметры определяют контекст выполнения тестов и пути к артефактам.

| Ключ                 | Значение                      | Описание                                                                                                                                                                                                                               |
|:---------------------|:------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`ui_engine`**      | `selenium` / `playwright`     | Селектор движка автоматизации. Определяет, реализация какого `DriverAdapter` будет инжектирована в тесты через SPI (Service Provider Interface). <br>Если оставить пустым (`null`), тесты запустятся без UI-драйвера (режим API-only). |
| **`browser`**        | `chrome` / `firefox` / `edge` | Таргет-браузер. Фреймворк будет искать соответствующий конфигурационный файл в папке `browsers_configs` (например, `chrome.yaml`).                                                                                                     |
| **`pages_dir`**      | Путь (String)                 | Относительный путь к директории, содержащей PageObject модели в формате `.yaml`. Дефолтное значение: `pages`.                                                                                                                          |
| **`testData_dir`**   | Путь (String)                 | Относительный путь к директории с тестовыми данными (Data Provider ресурсы). Дефолтное значение: `testData`.                                                                                                                           |
| **`logback_config`** | Имя файла                     | Имя конфигурационного файла для подсистемы логирования (Logback/SLF4J). Обычно: `logback.xml`.                                                                                                                                         |

## 2. Настройка перезапусков (`retry`)

Секция отвечает за настройку механизма `RetryAnalyzer` для TestNG. Это позволяет автоматически перезапускать упавшие
тесты для борьбы с нестабильными ("мигающими" / Flaky) сценариями.

Параметр **`count`** принимает целое число:

* Если указано **0**, механизм отключен. Тесты падают с первой попытки.
* Если указано **1** или больше, тест будет перезапущен указанное количество раз, прежде чем финально упасть.

```yaml
retry:
  count: 1
```

## 3. Конфигурация Cucumber (`cucumber_settings`)

Секция управляет запуском BDD сценариев, фильтрацией Gherkin-фич и распараллеливанием.

| Параметр       | Значение           | Описание                                                                                                                                                  |
|:---------------|:-------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`parallel`** | `true` / `false`   | Активация параллельного запуска сценариев. Реализовано через изменение `DataProvider` в рантайме.                                                         |
| **`threads`**  | `Integer`          | Размер пула потоков (Thread Pool Size). Используется только если `parallel: true`. Оптимальное значение зависит от CPU и памяти хоста.                    |
| **`run_by`**   | `tag` / `scenario` | Стратегия фильтрации тестов перед запуском.                                                                                                               |
| **`value`**    | `String`           | Значение фильтра. Поддерживает перечисление через запятую. <br>• Для тегов: `"@smoke, @regress"`. <br>• Для сценариев: `"Login Test, Registration Flow"`. |

---

## Пример файла runtime.yaml

```yaml
# Выбор движка и браузера
ui_engine: selenium
browser: chrome

# Пути к ресурсам
pages_dir: "pages"
testData_dir: "testData"
logback_config: logback.xml

# Настройки стабильности
retry:
  count: 0

# Настройки BDD раннера
cucumber_settings:
  parallel: true
  threads: 4
  run_by: tag
  value: "@regress"
```
