# Модуль Workspace

**`Workspace`** — это рабочий модуль конечного пользователя (автоматизатора).
Здесь находится весь проектный код: тесты, сценарии, описания страниц, тестовые данные и файлы конфигурации.

Остальные модули фреймворка (`core_lib`, `TestUtils`, `selenium_module`) являются библиотеками и не требуют модификации
при написании тестов. Вся разработка ведется только внутри `Workspace`.

Создайте проект со структурой описанной ниже. 
Выполните команду клонирования вашего проекта в папку `Workspace/src`:

```text
git clone <ССЫЛКА_НА_ВАШ_ТЕСТОВЫЙ_ПРОЕКТ> Workspace/src
```

Пометьте в IDE папку test/java как `Test Resources Root`.

## 🗂 Структура проекта

Ниже приведена схема расположения ключевых директорий и файлов.

```text
Workspace
└── src/test
    ├── java
    │   ├── runner      # Точка входа для запуска (CucumberRunnerTests)
    │   └── tests       # Место для Java-тестов (TestNG)
    │
    └── resources
        ├── configuration_files  # Конфигурация
        │   ├── browsers_configs # Настройки браузеров (chrome.yaml...)
        │   ├── browsers_drivers # Локальные exe-файлы драйверов
        │   └── runtime.yaml     # Глобальный конфиг запуска
        │
        ├── features    # BDD сценарии (Gherkin .feature)
        ├── pages       # Page Object модели (.yaml)
        └── testData    # Тестовые данные (.yaml)
```

## ▶️ Запуск тестов (`CucumberRunnerTest`)

Класс `runner.CucumberRunTests` — это точка входа для запуска тестов в пользовательском проекте.
Он должен наследоваться от **`BaseCucumberRunner`** (из модуля `TestUtils`), который берет на себя всю сложную логику
фильтрации и параллелизма.

### Конфигурация `@CucumberOptions`

Пользователь обязан настроить аннотацию в своем классе запуска, чтобы связать свои сценарии с логикой фреймворка.

**Обязательные параметры:**

* **`features`**: Указывает путь к папке с вашими сценариями. Обычно `"classpath:features"`.
* **`glue`**: Список пакетов, где Cucumber ищет реализацию шагов. **Важно подключить пакеты фреймворка:**
    1. `"steps"` — Базовые шаги (клики, ввод текста, навигация).
    2. `"TestUtils.CucumberUtils"` — Системные хуки (запуск браузера, отчеты).
    3. `"TestUtils.Assertion"` — Шаги проверок (Asserts).
    4. *(Опционально)* Ваши собственные пакеты с кастомными шагами.

**Пример реализации:**

```java
package runner;

import TestUtils.CucumberUtils.BaseCucumberRunner;
import io.cucumber.testng.CucumberOptions;

@CucumberOptions(
        features = "classpath:features",
        glue = {
                "steps",                   // Core steps
                "TestUtils.CucumberUtils", // System hooks
                "TestUtils.Assertion"      // Assertions
        },
        monochrome = true
)
public class CucumberRunTests extends BaseCucumberRunner {
    // Тело класса пустое. Вся логика наследуется.
}
```

## 🛠 Настройка запуска в IntelliJ IDEA

Для запуска BDD сценариев из IDE необходимо создать конфигурацию **TestNG** (так как наш раннер наследуется от
`AbstractTestNGCucumberTests`, а не использует нативный CLI Cucumber).

**Пошаговая инструкция:**

1. Откройте меню **Run** -> **Edit Configurations...**
2. Нажмите кнопку **+** (Add New Configuration) и выберите **TestNG**.
3. Заполните параметры согласно таблице ниже (см. скриншот):

| Параметр                    | Значение                  | Пояснение                                                                                                                                                              |
|:----------------------------|:--------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Test kind**               | `Class`                   | Мы запускаем конкретный Java-класс раннера.                                                                                                                            |
| **Class**                   | `runner.CucumberRunTests` | Укажите путь к вашему классу запуска.                                                                                                                                  |
| **VM options**              | `-ea`                     | *(Рекомендуется)* Enable Assertions. Включает проверки на уровне JVM.                                                                                                  |
| **Working directory**       | `.../Workspace`           | **Критически важно!** Путь должен указывать на корень вашего проекта/модуля. Именно отсюда фреймворк начинает поиск папки `src/test/resources` и файла `runtime.yaml`. |
| **Use classpath of module** | `Workspace`               | Выберите модуль вашего проекта, чтобы подтянулись все зависимости.                                                                                                     |

**Почему TestNG?**
Фреймворк использует TestNG как движок для оркестрации, параллельного запуска и ретраев. Нативный плагин "Cucumber Java"
в IDEA не сможет использовать нашу логику фильтрации и настройки потоков.

## ☕ Написание тестов на Java

Классические тесты пишутся в папке `src/test/java/tests`.
Вы можете создавать любую структуру пакетов внутри (например, по названию проекта или функциональности).

**Правила:**

1. Каждый тестовый класс должен наследоваться от **`BaseTest`**. Это обеспечит автоматическую инициализацию драйвера,
   данных и логгера.
2. Используйте аннотации TestNG (`@Test`, `@BeforeMethod`).
3. Используйте встроенные объекты `mouseSteps`, `navigationSteps`, `assertUtil` для написания логики.

## 🥒 Написание сценариев на Cucumber

BDD сценарии размещаются в папке `src/test/resources/features`.
Поддерживаются файлы с расширением `.feature`.

**Запуск:**
Запуск сценариев производится через класс `runner.CucumberRunnerTest`.
Фильтрация тестов (какие именно запускать) настраивается в файле `runtime.yaml` (секция `cucumber_settings`).

## 📄 Описание страниц (Page Objects)

Вместо Java-классов страниц фреймворк использует **YAML-файлы**.
Они должны лежать в папке `src/test/resources/pages`.

**Принцип работы:**
Фреймворк сканирует эту папку при старте. Имя файла или путь к нему не важны.
Важно только содержимое поля **`name`** внутри YAML файла.

**Пример (`LoginPage.yaml`):**

```yaml
PageInfo:
  name: "Страница Входа"  # <--- По этому имени шаг openPage найдет файл
  url: "/login"
  project: "MyProject"

elements:
  Кнопка Войти:
    type: button
    locator:
      by: css
      value: "button#login"
```

**Использование:**
`openPage("Страница Входа")` — фреймворк найдет этот файл, прочитает URL и откроет его.

## 💾 Тестовые данные (Test Data)

Данные для тестов хранятся отдельно от кода в папке `src/test/resources/testData`.
Фреймворк использует механизм **Data Binding по имени сценария**.

**Принцип связывания:**

1. У каждого теста есть имя:
    * **Cucumber:** Название `Scenario: ...` в feature-файле.
    * **Java:** Значение `@Test(description = "...")`.
2. В файлах тестовых данных ищется блок, где поле `Сценарий` совпадает с именем вашего теста.

**Пример (`LoginData.yaml`):**

```yaml
- Сценарий: "Успешный вход в систему"  # <--- Имя теста
  Тестовые данные:
    Login: "admin"
    Password: "123"
```

**Использование в тесте:**

* **Java:** `TestDataService.get("Login")` вернет `"admin"`.
* **Cucumber:** Использование плейсхолдера `{Login}` в шагах автоматически подставит `"admin"`.

## ⚙️ Конфигурация

Все настройки лежат в `src/test/resources/configuration_files`.

* **`runtime.yaml`** — Главный файл. Здесь выбираем браузер (`chrome/firefox`), среду (`selenium`), потоки и ретраи.
* **`browsers_configs/*.yaml`** — Тонкие настройки каждого браузера (headless, размеры окна, аргументы).
