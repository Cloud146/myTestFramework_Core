# Модуль core_lib (Ядро фреймворка)

`core_lib` — это фундаментальный модуль фреймворка, содержащий всю бизнес-логику работы с тестовыми данными,
конфигурацией и абстракциями драйверов. Это "скелет" системы, на который наращиваются конкретные реализации (например,
Selenium или Playwright).

Этот модуль **не содержит** тестов и **не привязан** к конкретной реализации UI-драйвера (напрямую не инициализирует
`ChromeDriver` или `FirefoxDriver`). Вместо этого он определяет **контракты (интерфейсы)**, которым должны следовать
подключаемые модули.

---

## Основные задачи модуля

1. **Управление конфигурацией (Config Management):**
   Чтение и валидация глобальных настроек (`runtime.yaml`) и конфигураций браузеров (`chrome.yaml`, `firefox.yaml`).
   Предоставление этих данных остальным частям системы в виде типизированных Java-объектов.

2. **Движок Page Object (YAML Engine):**
   Уникальная особенность фреймворка — хранение локаторов и описаний страниц не в Java-классах, а в **YAML-файлах**.
   `core_lib` отвечает за поиск этих файлов, их парсинг, кэширование и превращение в объекты, готовые к использованию в
   тестах.

3. **Слой абстракции драйвера (Driver Abstraction Layer):**
   Определяет единый API (`DriverAdapter`) для взаимодействия с браузером. Тесты, написанные с использованием
   `core_lib`, вызывают методы `clickElement` или `openUrl`, не зная, какой именно инструмент (Selenium, Playwright,
   Appium) выполняет это действие "под капотом".

4. **Инфраструктура (Infrastructure):**
   Включает в себя централизованную систему логирования (SLF4J/Logback wrappers), обработку ошибок (`ErrorBuilder`) и
   утилиты для работы с путями к файлам.

---

## Архитектурные принципы

Модуль построен на принципе **Dependency Inversion (Инверсия зависимостей)**.

* Высокоуровневые компоненты (шаги Cucumber, тесты) зависят от абстракций, описанных в `core_lib`.
* Низкоуровневые компоненты (модуль `selenium_module`) реализуют эти абстракции.

Это позволяет менять движки автоматизации (например, мигрировать с Selenium на Playwright) без необходимости
переписывать код самих тестов. Тесты зависят только от ядра.

---

## Структура пакетов (High-Level)

* **`browsers`** — POJO-модели конфигураций браузеров и базовые фабрики.
* **`config`** — Чтение YAML-конфигов (RuntimeReader).
* **`driverAdapter`** — Интерфейсы (контракты), описывающие поведение идеального драйвера.
* **`FileUtils`** — Логика работы с файловой системой: загрузчики страниц, поиск тестовых данных.
* **`data`** — Модели данных для страниц (PageModel, ElementDefinition).
* **`logging` / `ErrorUtils`** — Служебные утилиты.
