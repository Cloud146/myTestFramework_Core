# Пакет logging

Пакет **`logging`** отвечает за инициализацию, настройку и унификацию системы логирования во фреймворке.

Фреймворк использует **SLF4J** (Simple Logging Facade for Java) как единый интерфейс логирования и **Logback** как его
реализацию.
Особенностью пакета является механизм перехвата логов от сторонних библиотек (Selenium, Netty), которые используют
устаревший `java.util.logging` (JUL), и перенаправление их в единый поток Logback.

---

## 1. Класс `Log`

Утилитарный фасад для получения экземпляров логгера.
Его использование предпочтительнее прямого вызова `LoggerFactory`, так как это позволяет в будущем легко подменить
реализацию логирования без рефакторинга всего кода.

**Паттерн:** Factory Method / Wrapper.

| Метод     | Параметры        | Описание                                                                                                                                       |
|:----------|:-----------------|:-----------------------------------------------------------------------------------------------------------------------------------------------|
| **`get`** | `Class<?> clazz` | Создает логгер, привязанный к имени переданного класса. Это стандартный способ, позволяющий видеть в логах, из какого класса пришло сообщение. |
| **`get`** | `String name`    | Создает именованный логгер. Полезно для логирования абстрактных компонентов (например, `"DriverFactory"` или `"TestLifecycle"`).               |

---

## 2. Класс `LogbackConfigurator`

Отвечает за динамическую конфигурацию Logback на основе настроек из `runtime.yaml`.
Это позволяет менять уровни логирования (INFO/DEBUG/TRACE) или формат вывода (файл/консоль), просто редактируя
`logback.xml`, без перекомпиляции кода.

### Методы

| Метод                 | Логика работы                                                                                                                                                                                                                                                                                                                                                             |
|:----------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`initFromRuntime`** | **Инициализатор конфигурации.**<br>1. Считывает имя файла конфига (`logback_config`) из `RuntimeReader`.<br>2. Находит этот файл в ресурсах (`classpath`). Если не найден — падает с ошибкой.<br>3. Получает контекст Logback (`LoggerContext`).<br>4. Сбрасывает текущую конфигурацию (`context.reset()`).<br>5. Применяет новую конфигурацию через `JoranConfigurator`. |

---

## 3. Класс `JulBridge` (Java Util Logging Bridge)

Решает проблему "зоопарка логгеров". Многие библиотеки (например, Selenium WebDriver internals) пишут логи через
стандартный `java.util.logging` (JUL). По умолчанию эти логи идут мимо SLF4J и могут теряться или дублироваться в
консоли в неправильном формате.

Этот класс устанавливает "мост", который перехватывает все JUL-сообщения и отправляет их в SLF4J.

### Методы

| Метод      | Логика работы                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
|:-----------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`init`** | **Точка входа (Bootstrap).** Вызывается листенером (`LoggingBootstrapListener`) при старте тестов.<br><br>**Алгоритм:**<br>1. Логирует старт инициализации.<br>2. Вызывает `LogbackConfigurator.initFromRuntime()` для настройки основного логгера.<br>3. `LogManager.getLogManager().reset()` — сбрасывает стандартные настройки JUL (отключает дефолтный консольный вывод).<br>4. `SLF4JBridgeHandler.removeHandlersForRootLogger()` — очищает старые хендлеры.<br>5. `SLF4JBridgeHandler.install()` — устанавливает мост. Теперь `java.util.logging` -> `SLF4J` -> `Logback`. |
