# Пакет driverAdapter.adapter_api_contracts

Этот пакет содержит набор атомарных интерфейсов (контрактов), которые описывают конкретные группы действий пользователя.
Вместе они формируют полный API `DriverAdapter`.

Такая декомпозиция (Interface Segregation Principle) позволяет легко расширять функциональность фреймворка, добавляя
новые контракты (например, `JavascriptAdapter`, `FrameAdapter`) без необходимости переписывать гигантский монолитный
интерфейс.

---

## 1. Пакет `interaction` (Взаимодействия)

Описывает активные действия пользователя с элементами страницы.

### Интерфейс `MouseAdapter`

Контракт для действий мышью.

| Метод                    | Параметры            | Описание                                                        |
|:-------------------------|:---------------------|:----------------------------------------------------------------|
| **`clickElement`**       | `String elementName` | Выполняет одиночный клик левой кнопкой мыши по центру элемента. |
| **`doubleClickElement`** | `String elementName` | Выполняет двойной клик по элементу.                             |
| **`rightClickElement`**  | `String elementName` | Выполняет клик правой кнопкой мыши (вызов контекстного меню).   |

### Интерфейс `InputAdapter`

*В текущей версии пуст. Зарезервирован для методов ввода текста (`typeText`), очистки полей (`clear`) и загрузки
файлов.*

---

## 2. Пакет `element` (Состояние и Данные)

Описывает методы для получения информации об элементах.

### Интерфейс `TextAdapter`

Контракт для чтения контента.

| Метод                    | Параметры            | Описание                                                                                                                                     |
|:-------------------------|:---------------------|:---------------------------------------------------------------------------------------------------------------------------------------------|
| **`getTextFromElement`** | `String elementName` | Возвращает видимый текст элемента. Должен игнорировать скрытый текст и обрезать пробелы (trim), если это предусмотрено реализацией драйвера. |

### Интерфейс `ElementStateAdapter`

Контракт для проверки состояния (State) элементов. Методы этого интерфейса обычно возвращают `boolean` и не должны
падать с ошибкой, если элемент отсутствует (должны возвращать `false`).

| Метод                    | Описание и Ожидаемое поведение                                                                                        |
|:-------------------------|:----------------------------------------------------------------------------------------------------------------------|
| **`isElementDisplayed`** | Проверяет, что элемент **присутствует в DOM** И **виден** пользователю (имеет высоту/ширину > 0, не скрыт через CSS). |
| **`isElementPresent`**   | Проверяет только **наличие в DOM-дереве**. Элемент может быть невидим. Используется для проверки скрытых полей.       |
| **`isElementEnabled`**   | Проверяет интерактивность элемента (отсутствие атрибута `disabled`). Обычно применяется к кнопкам и полям ввода.      |

---

## 3. Пакет `navigation` (Навигация)

Управление адресной строкой и историей браузера.

### Интерфейс `NavigationAdapter`

| Метод         | Параметры    | Описание                                                                                      |
|:--------------|:-------------|:----------------------------------------------------------------------------------------------|
| **`openURL`** | `String url` | Открывает указанный абсолютный URL в текущем окне браузера. Ожидает полной загрузки страницы. |

---

## 4. Пакеты-заглушки (Reserved)

Следующие интерфейсы созданы для будущей реализации, чтобы зафиксировать структуру API.

* **`AlertAdapter`** (`alerts`): Для работы с нативными JS-алертами (`accept`, `dismiss`, `getText`).
* **`WaitAdapter`** (`waits`): Для реализации умных ожиданий (Hard waits, Wait for element to disappear).
