# Пакет driverAdapter

Пакет **`driverAdapter`** — это сердце абстракции работы с браузером.
Здесь определены ключевые интерфейсы и механизмы, позволяющие тестам не зависеть от конкретной библиотеки
автоматизации (Selenium, Playwright).

Пакет реализует паттерн **Adapter (Адаптер)**, скрывая реализацию (например, Selenium WebDriver) за единым фасадом.

---

## 1. Интерфейс `DriverAdapter`

Это "супер-интерфейс", описывающий **все возможности**, которые фреймворк ожидает от UI-драйвера.
Он не содержит методов сам по себе, а является агрегатором более мелких, тематических интерфейсов (контрактов) из пакета
`driverAdapter.adapter_api_contracts`.

**Назначение:**
Любой модуль, претендующий на роль движка автоматизации (Selenium Module, Playwright Module), обязан предоставить класс,
реализующий этот интерфейс.

**Состав (Наследуемые контракты):**

* `AlertAdapter` — работа с всплывающими окнами (alert/confirm).
* `ElementStateAdapter` — проверки состояния (виден/скрыт/активен).
* `TextAdapter` — получение текста элементов.
* `InputAdapter` — ввод текста, работа с полями.
* `MouseAdapter` — клики, ховеры, драг-н-дроп.
* `NavigationAdapter` — открытие URL, переходы вперед/назад.
* `WaitAdapter` — явные ожидания.

**Собственные методы:**

| Метод         | Описание                                                                                                                 |
|:--------------|:-------------------------------------------------------------------------------------------------------------------------|
| **`close()`** | Обязательный метод для корректного завершения сессии (закрытия браузера/контекста). Вызывается фреймворком в `tearDown`. |

## 2. Класс `AdapterHolder`

Класс управления контекстом драйвера. Реализует паттерн **Thread-Local Storage**.
Позволяет хранить экземпляр `DriverAdapter` отдельно для каждого потока выполнения тестов.

Это критически важный компонент для **параллельного запуска**: благодаря ему тест в Потоке-1 не может случайно отправить
команду в браузер Потока-2.

### Методы

| Метод                                  | Видимость       | Логика работы                                                                                                                                                                                                                                 |
|:---------------------------------------|:----------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`set`**<br>(`DriverAdapter adapter`) | `public static` | Сохраняет переданный адаптер в `ThreadLocal` переменной текущего потока. Вызывается при инициализации теста (`BaseTest.setUp`).                                                                                                               |
| **`get`**                              | `public static` | Возвращает адаптер, привязанный к текущему потоку.<br>**Важно:** Если адаптер не был инициализирован (метод `set` не вызывался), выбрасывает `IllegalStateException`. Это защищает от ситуаций "NullPointerException где-то в глубине теста". |
| **`clear`**                            | `public static` | Удаляет ссылку на адаптер из текущего потока. Обязателен к вызову в конце теста (`@AfterMethod`), чтобы избежать утечек памяти и использования "грязного" драйвера следующим тестом в этом потоке.                                            |

## 3. Интерфейс `DriverAdapterFactory`

Контракт для фабрики, создающей экземпляры `DriverAdapter`.
Используется механизмом SPI (Service Provider Interface) для динамического обнаружения и загрузки нужного движка.

**Принцип работы:**
При старте тестов `AdapterManager` сканирует все подключенные JAR-файлы и ищет реализации этого интерфейса.

### Методы

| Метод                 | Описание                                                                                                                                                              |
|:----------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`getEngineName()`** | Возвращает уникальное имя движка (например, `"selenium"`, `"playwright"`). Это имя используется в `runtime.yaml` (ключ `ui_engine`) для выбора конкретной реализации. |
| **`create()`**        | Создает и возвращает новый экземпляр `DriverAdapter`. Здесь происходит вся "магия" запуска браузера.                                                                  |
